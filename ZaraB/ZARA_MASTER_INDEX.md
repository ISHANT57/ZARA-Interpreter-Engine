## ✨ FINAL TIPS

### What Examiners Look For
1. **Understanding** - Do you really understand, not just memorize?
2. **Communication** - Can you explain clearly?
3. **Problem-solving** - Can you handle unexpected questions?
4. **Attention to detail** - Have you thought about edge cases?
5. **Confidence** - Do you own your work?

### How to Impress
```
"I implemented recursive descent parsing because it's simpler than LR
parsing for a DSL, and it allows me to generate meaningful error
messages. The operator precedence is handled through method nesting:
parseTerm handles * and /, while parseExpression handles + and
comparisons. This ensures that in 2 + 3 * 4, we get 14 not 20."

↑ Shows: Knowledge + Communication + Technical depth
```

### How to Recover from Mistakes
```
Examiner: "What about negative numbers?"
You: "That's a great point! Negative numbers aren't currently supported
as literals. We'd need to either add unary minus operator handling in
parsePrimary(), or change the grammar to allow signed numbers in the
tokenizer. This is definitely an improvement for v2!"

↑ Shows: Honesty + Problem-solving + Growth mindset
```
